## Is my tunnel URL private?

Not by default. Anyone who knows or guesses the URL can send requests to your local server. On Pro and Enterprise you can protect a tunnel with a password or an IP allowlist, and hand out expiring share links; see [Tunnel access](/dashboard/tunnel-access). Without that, tunnel a development server, not anything with real data, and protect sensitive routes in your own app. See [Limitations](/limitations#tunnel-urls-are-public).

## Where do I find my account slug?

It is the part of your tunnel URL before `--`, and the agent prints the whole URL when it connects (the `Public:` line). The dashboard doesn't display the slug on its own. See the [Quickstart](/getting-started/quickstart).

## Can I use my own domain?

Yes, on plans that include custom domains: add the hostname under **Custom domains**, create a TXT and a CNAME record, and the tunnel answers on it with HTTPS. See [Custom domains](/dashboard/custom-domains).

## How many tunnels can I run?

Each running agent is one tunnel, with its own label and URL. How many you can run at once depends on your plan — FREE 1, PRO 5, ENTERPRISE unlimited. See [Plans and limits](/reference/plans-and-limits#limits-that-depend-on-your-plan).

## Can I see the requests that came through?

Yes. The [request inspector](/dashboard/request-inspector) keeps each tunnel's recent requests and responses (bodies up to 16 KB, credentials hidden, for 24 hours) and can replay one. How many it keeps depends on your plan. The **Tunnels** page charts requests and errors over time. Run the agent with `--debug` for per-request lines in your terminal too.

## How long can a request take?

The hub's default wait is 120 seconds, and agent 1.0.20 and later wait for your server for as long as the hub allows minus two seconds (118 seconds on the default). Agent 1.0.19 and earlier gave up after 28 seconds. The SDK clients have their own 30 second defaults, so raise `timeout` on any client you call a slow route from. See [Troubleshooting](/troubleshooting#the-request-is-slow-or-times-out).

## Can I fake a response or simulate an outage?

Yes. A [mock API](/dashboard/mock-apis) is a whole fake API at a public URL, with no backend running: endpoints, rules, realistic data and delays, created from a template or an OpenAPI file. [Traffic rules](/dashboard/traffic-rules) change a running tunnel's traffic instead: answer one path with a mock, inject errors or delays, redirect, rewrite paths or change headers, without touching your app.

## Can I test my API from here, like with Postman?

Yes. The [API client](/dashboard/api-client) sends requests from the platform (so CORS never gets in the way), keeps them in collections your team shares, and checks responses without code. It imports Postman collections, OpenAPI documents, HAR files and curl commands. [`vhyxvoid test`](/cli/test) runs the same collection in CI and fails the build when a check fails.

## Can I write and share API docs, like with Swagger?

Yes. [API docs](/dashboard/api-docs) edits an OpenAPI spec in a form or as YAML, checked as you type. It publishes versions with a report of breaking changes. It shares rendered docs publicly, behind a password or on your own domain, with code samples and try-it. The same spec makes a mock API and a test collection in one click.

## Can my team talk and plan here instead of in another tool?

Yes. The [team space](/dashboard/team-space) has:

- chat with channels, direct messages, threads, mentions, reactions and live updates;
- markdown documents with history and comments;
- issues with a board.

Paste a link to a mock endpoint, request, load-test run or doc section and it shows as a card. Notifications arrive under the bell, and as a daily email digest.

## Can I load-test my API or monitor it?

Yes, on [Performance](/dashboard/performance): load tests against your own tunnels, mock APIs and verified domains (virtual users, ramp-up, pass/fail thresholds, a live chart), monitors that run an API client collection every few minutes and alert you when it fails, and per-endpoint latency and error analytics from real traffic.

## Do WebSockets work through the tunnel?

Partly. A simple connection can work, but Vite hot reload and socket.io don't reliably. See [WebSockets and hot reload](/troubleshooting#websockets-and-hot-reload-through-a-tunnel) and [Limitations](/limitations#websockets-through-a-tunnel-are-partial).

## Can I use the SDK in the browser?

No. It runs on Node.js only, and its WebSocket client takes your API key secret, which must never reach a browser. In a browser, call the tunnel URL with `fetch`. See [SDK overview](/sdk/overview).

## What happens to requests while my agent reconnects?

By default they are not held and replayed: the caller gets an error, and a `POST` that was in flight may or may not have reached your server. Make handlers idempotent. Turn on the tunnel's [webhook inbox](/dashboard/webhook-inbox) to have `POST`, `PUT`, `PATCH` and `DELETE` requests that arrive while it is offline stored and delivered when it reconnects. See [Limitations](/limitations#requests-dont-survive-agent-disconnects).

## I lost my API key secret. Can I see it again?

No, it is shown once and only a hash is stored. [Rotate the key](/dashboard/api-keys#rotate-a-key) to get a new secret (a paid-plan feature), or create a new key.
