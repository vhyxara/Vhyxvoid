By the end of this page you'll have a local server reachable at a public HTTPS URL and will have called it from code. You need [Node.js](https://nodejs.org) (the packages here were tested on Node 24) and something already listening on a local port. Any HTTP server works; the examples use port `3000`.

## 1. Create an account and an API key

1. Sign up in the <Dash to="/register">dashboard</Dash> and follow the verification email.
2. Open your account's **API Keys** page and choose **Create**.
3. Give the key a name, pick the **DEV** environment, and keep the **`tunnel:connect`** scope selected. It is the only scope the agent needs.
4. Copy the **key ID** and the **secret** from the dialog that appears.

<Callout type="warn" title="The secret is shown once">
  VhyxVoid stores only a hash of it. If you lose it, rotate the key from the same page to get a new one.
</Callout>

<Callout>
  Production (**PROD**) keys need a paid plan. On the free plan, create a **DEV** key.
</Callout>

## 2. Run the agent

Save your credentials in a file in your project directory, and keep it out of git:

```bash title=".env.vhyxvoid"
VHYXVOID_API_KEY=vhyxvoid_dev_xxxxxxxx
VHYXVOID_SECRET=your-key-secret
VHYXVOID_PORT=3000
```

```bash
echo ".env.vhyxvoid" >> .gitignore
```

The label defaults to `default` and the hub URL to `wss://hub.vhyxvoid.com/agent`, so you don't need to set them. Then start the tunnel:

```bash
npx @vhyxvoid/agent
```

<Callout type="warn" title="vhyxvoid init does not work right now">
  The CLI has an interactive `vhyxvoid init` command that is meant to write this file for you. In `@vhyxvoid/agent` 1.0.18 on Node 24 it exits silently after the secret prompt without writing anything, so create the file by hand as above. Details on the [CLI page](/integrations/standalone-cli).
</Callout>

When it connects you'll see:

```text
  ✅  Tunnel active

  Local:   http://localhost:3000
  Public:  https://acme--default.vhyxvoid.com

  Share the Public URL — it is stable and never changes.
```

You will also see internal debug lines starting with `[agent]` and `[batcher]`; they are noisy but harmless.

That `Public` line is your tunnel URL. It has the shape `https://<account-slug>--<label>.vhyxvoid.com`. The part before `--` is your account slug and the part after it is the label you chose.

<Callout type="info">
  If the agent connects but prints only `Local` and `Label` lines, it could not find an account slug for your key, so it has no public URL to show you. Check that the key belongs to the account you expect.
</Callout>

The agent keeps running until you stop it with Ctrl+C. If the connection drops it reconnects on its own, backing off up to five minutes between attempts.

## 3. Make a request through the tunnel

From any machine, use your own URL:

```bash
curl https://acme--default.vhyxvoid.com/
```

The request travels to the VhyxVoid hub, down the agent's connection, and to `http://127.0.0.1:3000/`. Your server's response, whatever it is, comes back the same way.

If it doesn't work, these are the responses VhyxVoid itself produces:

| Status | Meaning |
| --- | --- |
| `404` | No agent is registered for that URL. Start the agent, and check the slug and label. |
| `503` | The URL is registered but its agent is not connected right now. Restart the agent. |
| `413` | The request body was over 10 MB. |
| `504` | Your server didn't answer within 30 seconds. |

Anything else is your own server's response.

<Callout type="warn" title="Anyone with the URL can reach your server">
  The tunnel URL is public and carries no authentication. Only tunnel a server you're comfortable exposing, and protect sensitive routes in your own application. See [Limitations](/limitations).
</Callout>

## 4. Call it from code

To call the tunnel from a script, a CI job, or another server, install the SDK:

```bash
npm install @vhyxvoid/sdk
```

```js title="call-tunnel.js"
const { createClient } = require('@vhyxvoid/sdk')

const api = createClient({ accountSlug: 'acme', label: 'default' })

api
  .get('/')
  .then(({ status, data }) => console.log(status, data))
  .catch((err) => console.error(err.name, err.status ?? '', err.message))
```

Replace `acme` with the slug from your own URL. You can also set `VHYXVOID_ACCOUNT_SLUG` and `VHYXVOID_LABEL` in the environment and call `createClient()` with no arguments.

`get`, `post`, `put`, `patch`, and `delete` return `{ data, status, headers, ok }`. JSON responses are parsed, text comes back as a string, and binary responses come back as a `Buffer`. A non-2xx response throws a `ClientError` carrying the `status` and the response `data`.

<Callout type="warn" title="Use require(), not import, for now">
  In `@vhyxvoid/sdk` 1.0.1, `import { createClient } from '@vhyxvoid/sdk'` fails with `ERR_MODULE_NOT_FOUND`: the package's ESM entry point is declared but was never built. `require()` works. From an ES module, load it with `createRequire`:

  ```js
  import { createRequire } from 'node:module'

  const { createClient } = createRequire(import.meta.url)('@vhyxvoid/sdk')
  ```
</Callout>

The HTTP client is a plain `fetch` to your tunnel URL and sends no VhyxVoid credentials. That is why it needs your slug but no key.

## A note on retries

Requests sent to the tunnel while the agent is reconnecting can fail with `504` even though your server may have handled them. Retrying a `GET` is safe. Retrying a `POST` or `DELETE` can apply the change twice, so make those handlers idempotent if a duplicate would hurt. Details are on the [Limitations](/limitations) page.
