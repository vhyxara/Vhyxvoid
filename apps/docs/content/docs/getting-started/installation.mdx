VhyxVoid ships four npm packages. Pick by what you're doing:

| You want to… | Install | Guide |
| --- | --- | --- |
| Tunnel any local server, from the command line | `@vhyxvoid/agent` | [Quickstart](/getting-started/quickstart) |
| Start the tunnel from inside a Next.js app | `@vhyxvoid/next` and `better-sqlite3` | [Next.js](/integrations/nextjs) |
| Start the tunnel from inside an Express or Fastify app (see the warning below) | `@vhyxvoid/middleware` | [Express](/integrations/express), [Fastify](/integrations/fastify) |
| Call a tunneled server from code | `@vhyxvoid/sdk` | [SDK overview](/sdk/overview) |

For most projects, install the one you need as a development dependency:

```bash
npm install --save-dev @vhyxvoid/agent
```

You can also run the agent without installing it, with `npx @vhyxvoid/agent`, as the quickstart does.

<Callout title="Native module">
  The agent depends on `better-sqlite3`, which includes a native component. On common platforms npm downloads a prebuilt binary; on others it compiles one, which needs a C++ toolchain. `@vhyxvoid/next` and `@vhyxvoid/middleware` bundle the agent but do not declare this dependency, so a fresh project must install `better-sqlite3` itself, or `@vhyxvoid/agent`, which brings it along. The [Next.js](/integrations/nextjs) page shows the error you get otherwise.
</Callout>

<Callout type="error" title="@vhyxvoid/middleware 1.0.3 currently crashes">
  The Express and Fastify integration in the published `@vhyxvoid/middleware` 1.0.3 fails at startup when credentials are set. Use the [CLI](/integrations/standalone-cli) for those frameworks until a fixed version is published. Details on the [Express](/integrations/express) page.
</Callout>

<Callout type="warn" title="The Next.js integration">
  Use `@vhyxvoid/next` for Next.js. `@vhyxvoid/middleware` is documented here for Express and Fastify only.
</Callout>
