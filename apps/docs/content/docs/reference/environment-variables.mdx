## Where the agent looks

- **CLI (`vhyxvoid`)** reads `.env`, `.env.local` and `.env.vhyxvoid` from the directory you run it in. Later files win, and all of them override variables already in your shell. Flags override everything. See the [CLI reference](/cli/reference).
- **`@vhyxvoid/next`** reads the same three files but never overrides a variable that is already set. Its options win over the environment.
- **`@vhyxvoid/middleware`** (Express and Fastify) reads only `process.env`. It does not read `.env.vhyxvoid`, so load your file yourself (for example with `dotenv`) before you call it.
- **The SDK** reads only `process.env`, and only when you don't pass the option.

## Tunnel request timeout

How long the hub waits for your server to answer a tunnelled request is set on the hub, with `TUNNEL_REQUEST_TIMEOUT_MS`. It isn't a setting for the agent, the SDK or the dashboard: you can't change it from your side.

{/* generated:begin env-timeout · do not edit; run `pnpm --filter @vhyxvoid/docs generate` */}
| Variable | Default | Allowed range |
| --- | --- | --- |
| `TUNNEL_REQUEST_TIMEOUT_MS` | 120000 ms (120 s) | 5000 to 600000 ms (5 s to 600 s); anything else is ignored with a warning and the default is used |
{/* generated:end env-timeout */}

The hub's default is 120 seconds. Whoever operates the hub can set it anywhere in the range; a value outside the range is ignored with a warning and the default applies.

Three things to know about it in practice:

- **Your server's own limit can be shorter.** `@vhyxvoid/agent` 1.0.19 and earlier stop waiting for your local server after 28 seconds, whatever the hub allows. From 1.0.20 the agent uses the time the hub sends with each request (the hub's timeout minus two seconds, so 118 seconds on the default). `@vhyxvoid/next` and `@vhyxvoid/middleware` bundle the agent and have this from 1.0.5.
- **What a caller sees.** If your server is too slow, the caller gets a `502` whose message says `Local backend on port 3000 is not responding: timeout of 118000ms exceeded` (the number is the agent's wait in milliseconds; `28000` on 1.0.19 and earlier). A `504` (`Agent did not respond in time`) means the agent didn't answer at all. See [HTTP status codes](/reference/http-status-codes).
- **The SDK has its own timeouts.** The HTTP client's `timeout` (30 s by default) and `TunnelClient`'s (30 s in 1.1.0) are measured in your process. See [SDK errors](/sdk/errors).
