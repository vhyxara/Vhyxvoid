Open **Tunnels** under your personal workspace or under an organization in the sidebar. You start tunnels with the [agent](/docs/cli/reference) or an [integration](/docs/integrations/nextjs); this page shows them, their traffic and their history, and lets owners and admins stop an agent. Everyone in a workspace can see its page.

## Agents

The **Agents** card lists the agents connected right now and refreshes every 15 seconds. For each one:

| | |
| --- | --- |
| Health | **Healthy** (answering the hub's pings every 10 s), **Lagging** (missed one: a busy machine or slow network) or **Not responding** (missed several; the hub drops it soon) |
| Version | The agent's version, with **Update available** when it is older than the version the platform recommends, or **Too old** when it is below the oldest version the platform accepts |
| Up for, Last ping | How long it has been connected, and when it last answered |
| In flight | Requests waiting for its answer right now |
| Key | The API key it signed in with (marked when it expires within 7 days); links to API keys |
| From | The address it connects from (owners and admins only) |

Click a URL to copy it. When agents run an older version, a note above the list gives the update command (`npm i -D @vhyxvoid/agent@latest`, then restart the agent). **Show disconnects** lists the last 24 hours of disconnections, including those the hub made for unresponsive agents.

**Stop** (owners and admins) disconnects one agent: the agent prints "Stopped from the dashboard by &lt;your name&gt;" and exits instead of reconnecting, so someone has to start it again. Requests to its URL then get the usual offline answer (or the [webhook inbox](/docs/dashboard/webhook-inbox) or an [offline traffic rule](/docs/dashboard/traffic-rules) takes them). Each stop is recorded on the [Activity](/docs/dashboard/activity) page. To cut off an agent for good, revoke its key under API keys instead.

## Traffic

The **Traffic** card charts the requests that reached your tunnels' public URLs, stacked as successful, `4xx` and `5xx` answers, for the **last hour** (one bar per minute), **24 hours** (per 15 minutes) or **7 days** (per 2 hours). Above the chart: total requests, the share of server errors, the number of client errors and the average time to answer. Pick a **Tunnel** to see one tunnel only, or click a name in **Busiest tunnels**.

Hover a bar (or focus the chart and use the arrow keys) for its numbers; **Show as table** lists every bar. Figures arrive within about a minute and are kept for 7 days. They count what callers received, including `502`/`504` answers when your local server was down. The dashboard overview shows the same chart for your personal workspace once you have a tunnel.

## Session history

Below it, **Session history** is a table with one row per connection an agent has made:

| Column | Shows |
| --- | --- |
| Agent | The label and the agent's ID. |
| Status | `CONNECTED`, `DISCONNECTED`, or `EVICTED` (the connection was dropped because the agent stopped responding). |
| API key | The name of the key it used. |
| Connected | When the session started. |
| Duration | How long it lasted, as milliseconds, seconds or minutes. A dash means no duration has been recorded, for example while the session is still running. |

You can search, filter by status, and sort by agent, status or connection time. A restart of the agent, or a dropped connection that reconnects, starts a new row.

## What the page doesn't show

Individual requests are in the [request inspector](/docs/dashboard/request-inspector); who connected and disconnected when, together with every other change in the workspace, is on the [Activity](/docs/dashboard/activity) page.

## When a tunnel isn't listed

If your agent prints its public URL but is missing from **Agents**, wait for the next 15 second refresh and reload. If the agent isn't running, or has stopped reconnecting, requests to its URL get a `503`. See [Troubleshooting](/troubleshooting).
