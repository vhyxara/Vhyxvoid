Public pages are content entries edited under **Website content** in the console. Nothing on the marketing site needs a deploy to change. Blog posts have their own screen: see [Blog](/operators/blog).

## Kinds of content

| Kind | Slug | What it renders |
| --- | --- | --- |
| Landing page | `home` | The home page: hero and terminal sample, stats, features, steps, request-flow diagram, use cases, FAQ, closing call to action. |
| Pricing page | `pricing` | Plan cards and FAQ. Plan *limits* in the comparison table come live from the plan settings, so they never disagree with what is enforced. |
| Page | anything else, e.g. `about`, `contact`, `legal/privacy` | A page at `/<slug>`, written in the rich text editor. |
| Footer menu | `footer` | The footer of every page: columns of links, in order. |

The landing and pricing editors are forms. Pages and the footer have their own editors, below.

## Pages

**New page** asks for a title and a slug; the page is served at `/<slug>` (for example `/about`). Slugs the website already uses are refused: `login`, `register`, `pricing`, `docs`, `support`, `dashboard`, `organizations`, `api`, `p`, `blog`, the language codes and the others in `RESERVED_PAGE_SLUGS` (packages/content). The website's own pages always win over a page with the same path, so a page can never hide one.

The editor works like a word processor: headings, bold, italic, strikethrough, inline code, links, bulleted and numbered lists, quotes, code blocks, tables and dividers, with undo. **Markdown** switches to the page's source, for pasting or bulk edits.

Pages are stored as markdown, and the website shows them with raw HTML switched off. So a page can't run scripts or embed other sites, and colours and fonts follow the website's design rather than the page. Links can go to `https://`, `mailto:`, a path on the site (`/pricing`) or a section (`#faq`).

Pages that used to live at `/p/<slug>` redirect permanently to `/<slug>`. A path with no page answers a real 404.

Each entry has a search title and description for search results and link previews. The [SEO](/operators/seo) screen shows how every page does in search, can override those per address, and lists the missing addresses visitors hit, so you can redirect them.

### Contact form

**+ Contact form** places a contact form in the page (one per page). Visitors enter their name, email, an optional subject and a message. Each message:

- is listed under **Messages** in the console (unread first, then read; archived ones under *Archived*), where it can be marked unread, archived or deleted, and replied to by email;
- is emailed to the **Support email** setting, with the visitor's address as Reply-To.

Spam protection:

- A hidden field that people never fill. Filled ones are dropped without telling the sender.
- A limit of 5 messages per 10 minutes per address.
- Optionally, a Cloudflare Turnstile check, which most visitors pass without clicking anything. To turn it on:
  1. Create a widget in the Cloudflare dashboard, for the website's domain.
  2. Put its secret key in the API's `TURNSTILE_SECRET_KEY` (see [Deployment](/operators/deployment)).
  3. Put its site key in the **Captcha site key** setting (Support).

  The form then asks for the check and the API refuses messages without a valid one. If Cloudflare can't be reached, the API answers 503 rather than letting messages through unchecked. The **Contact form** setting under Support switches the form off; pages then show the support email address instead.

In the markdown source the form is a line holding only `{{contact-form}}`.

## Footer menu

Until you publish a footer menu, the footer is built in: Product (Features, Pricing, Docs), Company (Support, and Status, GitHub and X when those settings are set) and Legal (Terms of Service, Privacy Policy).

*Customize Footer menu* on the Website content screen creates the footer menu as a copy of that footer, so nothing disappears when you switch. Then:

- **Columns**: up to 6, each with a title. An empty column is not shown.
- **Links**: up to 12 per column. A link goes to **a page** (picked from the list) or **a URL** (`https://…`, `mailto:…` or a path such as `/pricing` or `/#features`), and can open in a new tab.
- **Order**: drag a column or a link by its ⠿ handle, or focus the handle and use Space and the arrow keys. *Column* moves a link to another column.

A link to a page shows only while that page is published, so unpublishing or deleting a page takes it out of the footer at the same time.

## Draft, publish, roll back

- **Save draft** keeps a working copy. Visitors keep seeing the published version.
- **Publish** makes the working copy live. The website shows it on the next request when the website refresh is set up (`WEB_REVALIDATE_URL` and `WEB_REVALIDATE_SECRET` on the API, `REVALIDATE_SECRET` on the website; see [Deployment](/operators/deployment)); otherwise within a minute. Saving settings refreshes the site the same way.
- **Unpublish** takes your version offline. Entries that ship with a built-in default (home, pricing, terms and privacy) fall back to it; any other page answers 404; the footer goes back to the built-in one.
- Every publish keeps a **revision** (with an optional note). *Restore* copies an old revision into the working copy; publish to make it live.
- If another admin saved the same entry after you opened it, your save is refused with a message to reload; their changes are never overwritten silently. Reload, then make your change again.

If the API is unreachable, the website renders the built-in defaults rather than an error.

## Who can do what

`content.read` to view, `content.update` to save drafts and restore revisions, `content.publish` to publish and unpublish, `content.delete` to delete an entry. Deleting an entry that has a built-in default brings the default back. `contact.read` lists contact form messages; `contact.update` marks them read, archives and deletes them.

## Starting from built-in content

Until you customise them, home, pricing, terms, privacy and the footer show built-in content. The Website content screen lists these under *Built-in content you can customize*; click one to copy it into an editable entry. Have your legal team review the default terms and privacy pages before launch: they are a starting point, not legal advice.
