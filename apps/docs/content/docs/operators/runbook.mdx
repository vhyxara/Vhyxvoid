## Planned maintenance

1. Set an announcement (**Settings → Announcement banner**) a day ahead.
2. At the start, turn on `maintenance.enabled` with a message. Users see a maintenance screen; the user API answers 503. The admin console, public pages, Stripe webhooks and already-connected tunnels keep working.
3. Do the work, check **System**, turn maintenance off, clear the banner.

## A user is being abused or is abusing

- **Compromised user**: *Sign out everywhere*, then *Send password reset*. Their API keys are separate credentials: revoke them under **API keys**.
- **Abusive workspace**: *Suspend* the account (its agents are disconnected and cannot reconnect, its API keys stop working, workspace actions are refused) and disconnect its live tunnels under **Tunnels → Live**. Record why in the reason; it is kept in the admin audit log.
- **Abusive custom domain** (phishing on a customer's hostname): remove it under **Custom domains**; the hub stops serving it immediately and Caddy will not renew its certificate.
- **Too much load from one account**: lower its limits with an account override instead of suspending.

## Stop new tunnels quickly

Turn off `tunnels.newAgentsEnabled`. Connected agents keep running; new connections are refused within 30 seconds. Use it during an incident on the hub or to shed load.

## Close sign-ups

Turn off `auth.signupsEnabled`, or limit sign-ups to certain email domains with `auth.allowedEmailDomains` and `auth.blockedEmailDomains`.

## Health checks

| Check | Healthy |
| --- | --- |
| `GET https://api.vhyxvoid.com/health` | `{"status":"ok"}` |
| Hub `GET /health` (inside the Docker network) | 200 |
| Hub `GET /metrics` (inside the Docker network) | Prometheus text: connected agents, sockets, pending requests |
| `docker compose logs caddy` | No repeated ACME errors |
| Console **System** page | Postgres, Redis and hub all green |

## Custom domain does not work

1. In **Custom domains**, check its state. *Waiting for DNS*: the TXT record `_vhyxvoid.<host>` is missing or wrong. *DNS not pointing here*: verified, but the CNAME/A record does not lead to the custom domain target.
2. `dig +short CNAME <host>` and `dig +short A <host>` should give the target or its addresses. If the customer proxies the record through their own Cloudflare, ask them to set it to DNS only.
3. Certificate errors: `docker compose logs caddy` shows ACME failures (Let's Encrypt rate limits, port 80 blocked). Caddy retries by itself.

## Alerts are not arriving

- Each rule sends at most 12 notifications an hour; the rule's history shows suppressed ones.
- Email needs `RESEND_API_KEY`; webhooks must answer 2xx within 5 seconds and cannot point at private addresses. Each history entry shows what happened on each channel.
- `features.alerts` off stops evaluation. **System → Run alert checks now** runs it immediately; a 409 means another API instance holds the job.

## An admin is locked out

Five wrong passwords lock an admin account for 15 minutes; waiting is the fix. To unlock sooner, a super admin can set a new password for them under **Admin users**, or run `UPDATE "AdminUser" SET "failedLoginAttempts" = 0, "lockedUntil" = NULL WHERE email = '…';` against the database.

## Background jobs

| Job | Runs | Does | Run now |
| --- | --- | --- | --- |
| `alerts` | every minute | evaluates alert rules | **System → Run alert checks now** |
| `domains` | every 5 minutes | checks custom domain DNS | **Custom domains → Check DNS now** |
| `notices` | every 15 minutes | 80% / 100% usage and trial-ending notices (each once) | **System → Send due usage/trial notices** |
| `maintenance` | hourly | deletes sign-in sessions dead for over 7 days, old notice records | `POST /api/v1/admin/system/jobs/maintenance/run` |

Each runs on one API instance at a time (a lease in the `job_leases` table). A run-now answer of 409 means another instance is running it.

## Backups

Back up Postgres daily (`pg_dump` or your provider's snapshots) and test a restore. Redis holds only caches, counters and the live tunnel registry; losing it costs this month's usage counters, not accounts or keys.

## Routine

- Read the admin audit log weekly; export it for compliance as CSV.
- Watch **Billing** for past-due accounts and trials ending soon.
- Triage **Feedback**.
- Rotate `HUB_INTERNAL_SECRET` on the API and hub together. Never rotate `SERVER_HMAC_PEPPER`: every API key depends on it.
