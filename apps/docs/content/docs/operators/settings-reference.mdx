Settings are edited under **Settings** in the console. Each change is validated, written to the admin audit log, and picked up by every API and hub process within 30 seconds. *Reset* returns a key to its default.

Settings marked *public* are readable without signing in (the website uses them for the banner, footer links and sign-up switches). Never put secrets in a setting; secrets belong in environment variables.

## General

Product name and public links.

| Key | Type | Default | Public | What it does |
| --- | --- | --- | --- | --- |
| `general.productName` | string | `"VhyxVoid"` | yes | Product name. Shown in page titles, emails and the dashboard. |
| `general.tagline` | string | see admin panel | yes | Tagline. One line under the product name. |
| `general.statusPageUrl` | url | `""` | yes | Status page URL. Linked from the footer when set. |
| `general.twitterUrl` | url | `""` | yes | X / Twitter URL. Footer link when set. |
| `general.githubUrl` | url | `""` | yes | GitHub URL. Footer link when set. |

## Maintenance

Take the dashboard and API offline for users while admins keep working.

| Key | Type | Default | Public | What it does |
| --- | --- | --- | --- | --- |
| `maintenance.enabled` | boolean | `false` | yes | Maintenance mode. Users get a maintenance page and the user API answers 503. Admin panel, public pages, webhooks and running tunnels keep working. |
| `maintenance.message` | text | see admin panel | yes | Maintenance message. Shown to users while maintenance mode is on. |

## Sign-up and sign-in

Who can create an account and how.

| Key | Type | Default | Public | What it does |
| --- | --- | --- | --- | --- |
| `auth.signupsEnabled` | boolean | `true` | yes | Allow sign-ups. When off, new accounts can only join through an invitation. |
| `auth.allowedEmailDomains` | stringList | `[]` | no | Allowed email domains. Only these domains may sign up (e.g. company.com). Empty allows every domain. |
| `auth.blockedEmailDomains` | stringList | `[]` | no | Blocked email domains. Sign-ups from these domains are refused (disposable mail providers, for example). |

## Billing

Checkout and trial policy. Prices themselves live in Stripe.

| Key | Type | Default | Public | What it does |
| --- | --- | --- | --- | --- |
| `billing.mode` | enum (free, paid) | `"free"` | yes | Billing mode. free: everyone uses the product without paying (launch / early access); upgrades and pricing tiers are hidden. paid: plans can be bought through Stripe. Existing subscriptions keep working in either mode. |
| `billing.defaultPlan` | enum (FREE, PRO, ENTERPRISE) | `"FREE"` | yes | Plan for accounts that don't pay. The plan every account without a paid subscription gets. Raise it to PRO during a launch to be generous; edit each plan's limits under Plan limits. |
| `billing.freeModeMessage` | string | see admin panel | yes | Free mode message. Shown on the pricing and billing pages while billing mode is free. |
| `billing.stripePrices` | json | `{}` | no | Stripe price IDs. The recurring Stripe price for each paid plan, e.g. \{"PRO": "price_123", "ENTERPRISE": "price_456"\}. Overrides the STRIPE_*_PRICE_ID environment variables. Create prices in the Stripe dashboard. |
| `billing.checkoutEnabled` | boolean | `true` | yes | Allow upgrades. When off, the upgrade buttons are hidden and checkout is refused. |
| `billing.trialDays` | number 0–90 | `14` | yes | Trial length (days). Free trial on an account's first paid subscription only. 0 disables trials. |
| `billing.usageNotices` | boolean | `true` | no | Usage emails. Tell an account's owners and admins (in-app and email) when it reaches 80% and 100% of its plan's monthly requests, once per month each. The monthly limit is soft: nothing is blocked. |
| `billing.trialNoticeDays` | number 0–14 | `3` | no | Trial reminder (days before end). Remind owners and admins this many days before a trial ends (in-app and email, once per trial). Stripe's own 3-day notice is merged with it. 0 turns the reminder off. |

## Tunnels

Tunnel behaviour for every account.

| Key | Type | Default | Public | What it does |
| --- | --- | --- | --- | --- |
| `tunnels.customDomainTarget` | string | `""` | yes | Custom domain target. The hostname customers point their domains at with a CNAME (e.g. edge.vhyxvoid.com, an A record on your edge server). Empty disables adding custom domains. |
| `tunnels.recommendedAgentVersion` | string | `"1.1.0"` | yes | Recommended agent version. Agents older than this get an "update available" note on the dashboard's Agents card (they keep working). Set it to the newest published @vhyxvoid/agent after a release. Empty: no note. |
| `tunnels.minimumAgentVersion` | string | `""` | yes | Minimum agent version. The hub refuses agents older than this at connect time with an "update the agent" message (connected agents stay until they reconnect). For security fixes or protocol changes. Empty: any version may connect. |
| `tunnels.newAgentsEnabled` | boolean | `true` | no | Accept new agent connections. When off, the hub refuses new agent registrations (running tunnels stay up). For incidents. |

## Features

Turn product features on or off.

| Key | Type | Default | Public | What it does |
| --- | --- | --- | --- | --- |
| `features.requestInspector` | boolean | `true` | yes | Request inspector. The hub keeps recent requests of each tunnel (bodies cut at 16 KB, credentials hidden, 24 h) so users can inspect and replay them. How many per tunnel is the plan limit inspectorRequests. |
| `features.webhookInbox` | boolean | `true` | yes | Webhook inbox. Tunnels with their inbox on keep write requests (webhooks) that arrive while the agent is offline and deliver them when it reconnects. How many per tunnel is the plan limit inboxRequests. |
| `features.customDomains` | boolean | `true` | yes | Custom domains. Customers can serve a tunnel on their own hostname. Needs the edge (Caddy) and a target hostname under Tunnels. |
| `features.trafficRules` | boolean | `true` | yes | Traffic rules. Customers can add rules to a tunnel that answer with a mock, inject delays or errors, redirect, rewrite paths and set headers, applied by the hub before a request reaches the agent. How many per tunnel is the plan limit maxTrafficRules. Off: every rule is ignored at once. |
| `features.performance` | boolean | `true` | yes | Load tests, monitors and API analytics. Customers can load-test their own tunnels, mocks and verified custom domains (sent straight to the hub, never to other hosts), schedule monitors that run collections and feed MONITOR alerts, and see per-endpoint analytics. How much is the plan limits maxLoadTestVus, maxLoadTestSeconds, maxLoadTestRps, loadTestsPerDay, maxMonitors and minMonitorIntervalMinutes. Off: new load tests are refused, running ones stop within a second, monitors pause; analytics stay readable. |
| `features.teamSpace` | boolean | `true` | yes | Team space. Customers get chat (channels, direct messages, threads, mentions, reactions, live updates), documents (markdown pages in folders with history and comments) and a tracker (issues with status, assignee, labels, priority, due date, board), with in-app notifications and an email digest. How much is the plan limits maxTeamChannels, maxTeamDocs, maxTeamIssues and teamHistoryDays. Off: the team pages are read-only and live updates stop; nothing is deleted. |
| `features.aiAssist` | boolean | `true` | yes | AI assist. Members (and API keys with the ai:use scope) can draft a mock API or a test collection from a description, from traffic captured by the request inspector, or from an API spec. Drafts open in the editor and are never saved on their own. Needs ANTHROPIC_API_KEY on the API server; the prompt (the description, and the captured traffic or spec it is based on, with credentials removed) is sent to Anthropic. How many drafts is the plan limit aiRequestsPerMonth. Off: drafting is refused. |
| `features.apiDocs` | boolean | `true` | yes | API documentation. Customers can write OpenAPI specs in the dashboard (form or YAML, validated), publish versions with a breaking-change report, and share rendered docs publicly, behind a password or on their own domain, with try-it against a mock. How many is the plan limit maxApiSpecs; passwords and domains are protectedDocs and docsCustomDomains. Off: editing and publishing are refused and public docs pages answer 404; saved specs stay. |
| `features.apiClient` | boolean | `true` | yes | API client and tests. Customers can send requests from the dashboard through the platform's server-side runner (public addresses only), keep collections and environments, add checks and run collections. How much is the plan limits maxApiCollections, maxApiCollectionRequests and apiClientSendsPerMinute. Off: sending and runs are refused; saved collections stay. |
| `features.mockApis` | boolean | `true` | yes | Mock APIs. Customers can create hosted mock APIs that answer at a tunnel label's URL with no agent running (endpoints, response rules, templating, OpenAPI import). How many is the plan limits maxMockApis and maxMockEndpoints. Off: the hub stops answering from mocks. |
| `features.alerts` | boolean | `true` | yes | Alerts. Customers can create alert rules (tunnel offline, error rate, usage, inbox, domains) delivered by email, in-app and webhook. |
| `features.feedbackEnabled` | boolean | `true` | yes | Feedback form. Let signed-in users send feedback from the dashboard. |
