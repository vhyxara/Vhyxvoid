This section is for the people who run VhyxVoid: deploying it, configuring it, and looking after users. Everything here is done from the admin console or with one command; nothing needs a code change.

## The pieces

| Service | What it does | Default port |
| --- | --- | --- |
| `api` | REST API for the dashboard, admin console, billing webhooks and public site data. Runs database migrations on start. | 9000 |
| `hub` | Accepts agent connections and forwards public tunnel traffic to them. | 9001 |
| `web` | Marketing site and user dashboard (Next.js). | 3000 |
| `admin` | Operations console (Next.js). | 3000 |
| `nginx` | Public entry point: TLS for `*.vhyxvoid.com`, routes each hostname to the right service. Port 443 routes by hostname (SNI) so customers' custom domains reach Caddy. | 80, 443 |
| `caddy` | TLS for customers' custom domains, with certificates issued on demand. Not published; only nginx reaches it. | — |
| Postgres | Accounts, users, keys, settings, site content, audit logs. | 5432 |
| Redis (Upstash REST) | Rate limits, caches, tunnel registry, usage counters. | — |

## What you control from the admin console

- **Users and accounts**: search, suspend, reactivate, change plan limits per account, add notes, force sign-out.
- **API keys, tunnels and domains**: see every key, revoke one, see live agents and their versions, disconnect a tunnel, remove a customer's custom domain, and set the recommended and minimum agent version.
- **Traffic**: live platform traffic and the busiest accounts on the dashboard.
- **Billing**: subscriptions, invoices and payment status from Stripe, per account.
- **Logs**: user audit log, admin audit log (CSV export), and system health.
- **Settings**: maintenance mode, announcement banner, sign-up policy, trial length, checkout switch, plan limits, tunnel switches, support links, feature switches. See the [settings reference](/operators/settings-reference).
- **Content**: landing page, pricing page and any number of markdown pages (terms, privacy, about) with drafts, publishing and revision history. See [site content](/operators/content).
- **Admins and roles**: invite admins, give them roles built from abilities, reset an admin's password.

Changes to settings reach every API and hub process within 30 seconds. Published content reaches the website within a minute.
