`TunnelClient` keeps one WebSocket open to the hub and sends every call over it, signed with your API key. Reach for it when a Node.js process makes many calls and you would rather hold one connection than open a new HTTPS request each time. For everything else use the [HTTP client](/sdk/http-client), which needs no key.

<Callout type="error" title="Node.js only, and keep the secret on the server">
  `TunnelClient` is configured with your API key ID and secret. Put them in environment variables of a server process. Never put them in a browser bundle: anyone who loads the page would get the secret. The SDK can't be bundled for a browser anyway (it uses Node's `crypto` and `http` modules), so the page's advice for a browser is to call the tunnel URL with `fetch`. See [Limitations](/limitations#the-sdk-is-nodejs-only).
</Callout>

## Use it

```ts
import { TunnelClient } from '@vhyxvoid/sdk'

const tunnel = new TunnelClient({
  hubUrl: 'wss://hub.vhyxvoid.com/sdk',
  keyId: process.env.VHYXVOID_API_KEY!,
  secret: process.env.VHYXVOID_SECRET!,
  label: 'default',
})

await tunnel.connect()

const res = await tunnel.get('/users', { query: 'page=2' })
console.log(res.status, res.body, res.isLocal)

tunnel.disconnect()
```

How it behaves:

- **You must call `connect()` first.** A request on a client that isn't connected rejects with a `TunnelError` whose code is `AGENT_NOT_FOUND` and message `Not connected to hub. Call connect() first.` (checked on 1.1.0). If the connection itself fails, `connect()` rejects with a plain `Error` such as `Hub connection failed: connect ECONNREFUSED …`.
- **Local shortcut.** Unless you pass `localDiscovery: false`, each request first checks for an agent on the same machine (port 4242). If one answers, the request goes straight to the local server that agent forwards to, without passing through the hub or being signed, and `res.isLocal` is `true`. The check does not look at your `label` or account, so with a different agent running locally the request goes to that one's server. Pass `localDiscovery: false` when you want the hub to route the call.
- **Requests are JSON.** `post`, `put` and `patch` serialize their body with `JSON.stringify`.
- **Errors.** Failures reject with a [`TunnelError`](/sdk/errors#tunnelerror). A request that gets no answer in time rejects with `TunnelTimeoutError` (code `AGENT_TIMEOUT`). If the hub connection drops, every request still waiting is rejected with `AGENT_DISCONNECTED` (marked retryable). The client does not reconnect for you; call `connect()` again.
